# 信息架构（IA）——唯一归属约定

> 本文是**前端信息架构的唯一事实源**。新增/改动页面、板块、锚点前先读这一份。
> 违反本文的 PR 应在审查阶段退回。
>
> 背景：2026-11-12 加一条"市场风险"提示时，同一条信息需要改 **3 个页面**
> （`/today`、`/market`、`/candidates`）才保证到处可见 —— 这是"一条信息没有
> 唯一归属"的直接证据。本文把归属钉死，避免继续扩散。

## 一、核心原则

1. **一条信息只有一个"主页"**。其他页面只能放**一行摘要 + 跳转**，不得再实现一份。
2. **一个页面只回答一个问题**。页面标题 = 它回答的问题。
3. **同一句话只允许出现一次**（历史教训：同值重复堆叠，见 2026-11-09 前端重构）。
4. **不靠折叠求整洁**：信息该看就平铺（2026-11-09 老大明确要求）。
5. **降级要显式**：接口失败 ⇒ 明确提示可重试；返回空 ⇒ 明确说"数据源未覆盖"。
   两者文案必须不同，否则空面板会被读成"今天没数据"这句**假陈述**。

| 路由 | 左栏名 | **唯一负责回答** | 明确**不负责** |

## 四、新增信息时的检查清单

- [ ] 这条信息属于哪个模块？查第二节，**只有一个**答案
- [ ] 其他页面要展示吗？只允许「一行摘要 + `<Link>`」
- [ ] 文案是否与已有页面**重复**？重复就删，指向主页
- [ ] 接口失败时，用户看到的是"可重试"还是"没数据"？两者不能混
- [ ] 是否为它新增了锚点？锚点会让同一内容出现第二次，慎用

## 五、为什么不做"大重构"

历史上 `/today` 从"每日复盘"拆出过独立模块（2026-11-09），说明**拆页本身不是目标**，
减少重复渲染和口径漂移才是。故本文件的策略是：

1. 先**钉归属 + 停止新增重复**（本文 + 删死代码）；
2. 再逐页把重复块降级为摘要（一次一页，每页跑 `tsc --noEmit` + 手测）；
3. Streamlit 旧看板只做 legacy 标注，不投入重构。

一次性重写 14 个模块的路由与组件，风险远大于收益 —— 这是刻意的取舍，不是拖延。
