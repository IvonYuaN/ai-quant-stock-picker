## 用户主流程

今日先看我的风险提醒 → 持仓与自选同屏 → 复核消息和大盘 → 在交易软件操作 → 全局回录 → 自动建立风险规则 → 提醒处置。
导航仅今日、我的持仓、大盘、消息；候选与多 Agent 是辅助依据，历史量化验证留在离线和展开证据中。

## L4 触发依据图契约

原 PRD §4.2 要求展开 MACD 死叉对应的日线图并高亮触发位置。`basis_json`

- `kind="macd_dead_cross"`、`price_adjustment="none"`、`fast/slow/signal=12/26/9`。
- `trigger_date` 为日线触发日期，`source` 为该次检查输入说明；
  `points=[{date,close,dif,dea}]` 保存至多 60 日的显示快照。
- DIF/DEA 复用同次 L4 检查的全历史 EMA 结果，计算后再截显示窗口；
  不重新取最新行情，不复算不同口径的指标，不使用前复权价格。
- 仅有效 L4 死叉生成图形证据；无效价格、缺失/非法/重复/乱序日期不生成。
  服务层清洗日期、按自然日规范化稳定去重，并过滤未来日期。
- L4 服务检查验证参与 EMA 的全历史正价与有限值；异常明确记为未检查，
  保留已有 OPEN 提醒及其依据，不因计算失败误判条件解除。L2 仍按均线窗口检查。
- 图形与文本一起走既有事件持久化；OPEN 更新同次依据，终态历史不被新图覆盖。
  前端展开时才挂载图表，并标记触发日、DIF/DEA 下穿点及原始数值。
- 旧事件或不完整图形保留文字说明并显示缺图提示；图表加载失败仍有数值可复核。

### 实际使用反馈修正

- 同仓 L1/L5 等规则合并为一张股票卡；侧栏数量按持仓计数，规则事实留在展开证据。显示股票名，价格最多四位小数，避免浮点尾数。
- 风险收件箱按“今天可卖 · 需要复核”和“T+1 观察 · 明日才能卖”分区，并在每张卡明确“为什么需要复核”；旧提醒缺少 `position_id` 时按当前仓身份归并，避免同一标的重复成卡。
- 首次取得可信行情名称后写回持仓快照；后续行情源短暂失败仍显示上次已核验名称，不把代码伪装成股票名。
- 风险越线与处置方案分开：保留风险规则触发事实，展示市场、板块、个股的可核验依据与时效；单独触发 L1 不推出清仓，也不禁用做 T 观察。仅三维同交易日同步走弱时突出减仓/退出复核；缺失证据不当成弱势。做 T 观察意向不代表适合执行或能够解套。
- 频率默认口径：PRD §4.5 对 L4 写有“每日一次”，而 §7.2 的数据模型规定 `freq_mode` 默认 `once`；本实现按数据模型和降低重复提示的验收目标统一采用 `once`，用户仍可手动改为 `daily`/`always`，连续忽略两次才自动降为每日一次。
- 持有观察、减仓退出、做 T 观察三种人工方案按仓位原子持久化，刷新仍保留；选择方案不关闭风险、不改阈值、不记成交。做 T 不保证解套，实际卖出/回补分别回录并遵守 T+1。
- 打开中的可见页每分钟只读同步提醒，恢复焦点与页头刷新同步；后台页暂停，自动刷新不检查、不外发。读取失败保留已知风险数量。
- 回录成功按实际返回规则数量提示关联/启用条数；持仓标明已关联规则的强化盯盘。自选列表仍保留在浏览器，成功移出后追加租户隔离的 `/api/watchlist/removals` 审计记录，提醒中心合并显示服务端与本机记录；接口失败时保留本机记录，不阻断用户移除操作。
- 提醒规则默认采用 `once`，避免同一仓位在同一越线事实下重复打扰；`daily` / `always` 仍可由用户在规则设置中显式选择。该决策按 PRD 数据模型的默认值及“重复提示”实际反馈执行。
- 外发按仓位合并，租户锁内先保存固定批次与成员，再发送、原子确认；发送后本地写盘失败可凭成功回执恢复。无法确认外发结果的批次停止自动重发，并明示阻塞原因，避免因新增规则或并发检查重复通知。
