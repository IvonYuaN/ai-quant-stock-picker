# 实盘辅助工具竞品对标（竞析）

> 日期：2026-07-08 ｜ 调研范围：富途牛牛 / 同花顺 / 通达信 / 雪球组合 / 涨停雷达·九尾狐类打板工具 / Qlib 等开源量化
> 核心问题：**这些工具怎么组织"持仓 → 建议 → 提醒"的 loop，为什么用户信任它们**

---

## TL;DR（3 行）

1. **所有被信任的工具，首页的中心对象都是"我的持仓 / 我的自选"，没有一个是"今日推荐"。** 富途的入口是铃铛、通达信的入口是自选股+预警、Qlib 的产物是**目标持仓**（target position）而不是推荐榜。
2. **信任来自四个可验证属性**：对象稳定（每天看同一批票）· 输入可控（用户自己设条件/自己回录）· 输出可执行（触发即动作，不是又一份报告）· 不打扰（仅提醒一次/每日一次）。老大的系统恰好在**这四条上全灭**。
3. **"该卖提醒"在全行业没有一处依赖模型预测，全是确定性阈值**：硬止损 −5%、有效跌破 MA5、炸板/放量长上影、MACD 死叉、从最高价回撤 X%。可解释 = 可信任。我们手里现成的 `stop_loss.py` / `dynamic_stop.py` / `unified_risk.py` 就是这套东西，只是**接错了对象**（接回测而不是接实盘持仓）。

## 对标产品 loop 拆解

| 产品 | 中心对象 | 每天打开看什么 | "该卖"怎么提醒 | 值得抄的机制 |
|---|---|---|---|---|
| **富途牛牛 / 老虎** | **我的持仓 + 我设过的提醒**（双中心） | "我的提醒"总列表：跨股票聚合，只显示**触发了什么**；不显示"今日推荐" | 4 类提醒：**到价**（涨到/跌到/日涨跌幅超/3分钟·5分钟涨跌幅超）、**盘口**（成交量/成交额/换手率/买卖一量）、**指标**（MA/EMA/KDJ/RSI/MACD/BOLL，如"跌穿 MA30""MACD 死叉"）、**事件**（公告/评级变动）。配套**智能订单**：止损限价单、跟踪止损单（从最高价回撤 X% 自动上移触发价）、OCO 二选一 | ① **"我的提醒"是一个聚合收件箱**，不是分散在各股页面<br>② **提醒频率三档**：仅提醒一次 / 每日一次 / 持续提醒 —— 防打扰是产品功能不是 bug<br>③ 提醒**绑定个股对象**，用户动作链是"加自选 → 设条件"，不是"看推荐 → 决定"<br>④ 跟踪止损 = 卖出提醒的最高形态（动态阈值上行） |
| **同花顺** | **自选股 + 异动事件** | 盘中弹窗 / 声音；手机端个股页铃铛（拉升/放量/**炸板**），PC 端【智能】→短线精灵 / 个股雷达 / 鹰眼盯盘 | 手机预警勾选**快速拉升、大单异动、炸板**；PC 个股雷达自定义涨跌幅/量比/单笔成交量/换手率/震幅；支持自选股**批量异动提醒** | ① **炸板是一等公民提醒项** —— 打板场景的退出信号<br>② 批量监控以**自选股为范围**（不是全市场）<br>③ 社区共识反模式："**只设买入预警、不设风险预警**"是最常见误用 → 卖出提醒必须被产品主动引导，不能等用户自己配 |
| **通达信** | **自选股（监控范围）+ 条件预警** | 【功能】→【预警系统】→【条件预警设置】（Ctrl+Y）：添加品种范围（自选股/沪深A股/板块）→ 添加条件 → 弹窗/声音/邮件 | 条件预警四类：价格（跌破支撑/回踩均线）、量能（放量/缩量/巨量出货）、指标（MACD 金叉死叉/均线突破）、盘口（大单/挂单异动）。社区强调**量价双条件**过滤假突破 | ① 监控**范围**是显式配置对象（自选股）→ 范围即用户意图<br>② 条件是**可自查的公式**（用户看得懂触发依据）<br>③ 弹窗+声音双通道，且强调"条件别设太敏感" |
| **雪球组合** | **我的持仓 + 调仓理由** | 持仓比例变化、每一次调仓的**理由**、以及事后复盘（"三季度总结"：持仓比例对比 + 逻辑回顾 + 验证） | **无盘中提醒**。卖出纪律完全外化到"我写了为什么买/为什么卖"的公开记录 → 靠**承诺一致性 + 围观压力**自律 | ① 持仓是**时间序列**（比例变化），不是快照<br>② 每次操作强制附**理由**，形成可复盘账本<br>③ 复盘文章本身就是内容 → 持仓天然驱动用户回访 |
| **涨停雷达 / 九尾狐类打板工具** | **今天的排序第一名**（极度收敛） | 9:25 竞价排序（竞价爆量/高开幅度/封成比），**每天只做第一名，每天一支** | 卖出纪律写死在指标说明里：**−5% 无条件离场** / **有效跌破 5 日线** / 连板持有直到**放量长上影、炸板** | ① **输出收敛到 1 支** —— 信任来自"敢给唯一答案"<br>② 触发条件全是**盘面可观测事件**（炸板、长上影、跌破均线），不是模型分数<br>③ 盘中预警 + 盘后选股**两种模式分开**，不混在一个"今日推荐"里 |
| **Qlib / 开源量化** | **目标持仓（target position）** | 每日 workflow：收盘后拉新数据 → 增量预测 → 记录版本；开盘前 cron 跑 `predict` → score 排序 | 不做盘中提醒。退出靠 `TopkDropoutStrategy`：**每天只卖出掉出 topk+n_drop 的、买入新晋 topk 的**，其余持仓不动 → 换手率被压到极低 | ① **产物是目标持仓，不是推荐榜** —— 这是最关键的一条<br>② 每日订单 = 目标持仓 − 当前持仓的**差分**，天然稳定<br>③ 版本记录 + 冻结期参数不变 → 可复现、可追责 |

## 共同心智模型（1 段话）

**这六个工具没有一个把"今日推荐"放在中心位置，因为"今日推荐"这个对象本身就无法建立信任——它每天换一批，用户没有 mental model 可以挂靠。** 它们的共同心智模型是：**"系统是我的持仓 + 我的自选 + 我设过的条件"的持久层，每日新信息只是这个持久层上的增量事件。** 富途的中心是"我的提醒"收件箱（跨股票聚合、只报触发了什么、频率可控），通达信/同花顺的中心是"自选股作为监控范围 + 条件公式"，九尾狐把出票收敛到"今天的第一名"，Qlib 把产物定义成"目标持仓"而非"推荐榜"，雪球把持仓做成带理由的时间序列。所以用户信任它们，不是因为它们推荐得准，而是因为它们满足了四个可验证属性：**对象稳定**（每天看的是同一批票）、**输入可控**（条件/记录由用户自己写）、**输出可执行**（触发即动作，不是又一份报告）、**不打扰**（频率限制、只报变化）。反过来说，一个每天换一批候选、没有"我买了/卖了"输入、止损只跑在回测里的系统，恰好在这四条上全部违约——用户每天要重新建立一次"这系统今天想说什么"的认知成本，且无法把任何一条输出归因到自己的某个决定上。这才是"早中晚看三次都不一样 → 无法建立信任"的机制解释，不是内容质量问题。

## 功能分层建议

### P0（每天必看 · 构成新首页的全部）

| # | 功能 | 抄谁 | 为什么 P0 |
|---|---|---|---|
| 1 | **持仓 + 自选合并为一页「我的仓位」** | 雪球持仓页 / 富途持仓页 | 对象稳定性是信任的地基。当前 HoldingsPage / WatchlistPage 分裂 + ConceptsPage 独立，把"我的对象"拆成三处 |
| 2 | **「今日提醒」聚合收件箱** —— 只列**今天触发了什么**（持仓/自选范围内），每条给出触发依据 + 建议动作 | 富途"我的提醒" + 九尾狐盘面事件 | 这是把 `stop_loss.py` / `dynamic_stop.py` / `unified_risk.py` 接到实盘持仓的**唯一出口**。也是"该卖提醒"的落点 |
| 3 | **操作回录轻入口** —— 全局一条"我操作了 [代码/方向/价格/数量]" | 富途持仓成本设置 / 雪球调仓记录 | loop ⑥。`portfolio.py` 的 `add_holding`/`close_position` 数据结构已在，缺的是顺手入口。回录后该票自动进入"强化盯盘"，并累计出"我在这只票上的历史判断 → 实际结果"账本 |
| 4 | **今日候选（冻结快照）** —— 盘前生成后冻结，盘中只标"新增/失效"增量 | Qlib workflow 版本冻结 | 信任度最低的一项，但 T+1 决策窗口要求它稳定。**放在 P0 末尾**：它是入口（今天看什么），不是结论 |

**首页信息顺序（对齐用户 loop）**：`今日提醒（要处理的事，最显眼的红点） → 我的仓位 → 大盘 → 今日候选 → 消息流`

### P1（偶尔看 · 折叠进二级）

- **消息流（小道消息）** —— 用户优先级第一，但它是**输入源**不是**状态**，应折叠为提醒中心的一个 tab / 侧栏，而不是首页一整屏
- **大盘 / 情绪指数** —— 环境过滤器（打板纪律第一条"大盘不能大跌"），重要但只需一眼
- **个股研究页 / 自选详情** —— 深入查证时才进
- **NotesPage / ReportsPage** —— 报告类产出改为按需生成 + 可分享链接，不占导航位

### 砍掉 / 降级

| 项 | 处理 | 依据 |
|---|---|---|
| **ConceptsPage 独立成页** | 降级为「我的仓位」内的一个板块标签 | 用户明言板块页多余；打板场景里板块只作为"是否属于当下热点"的过滤条件，不值得独立成页 |
| **DSR / PBO 统计门禁** | 移入 `reports/` 离线产出，退出主界面 | 用户从不消费；它是研发质检，不是决策输入 |
| **CSCV 多变体回测** | 保留离线跑，结果只决定策略是否上线 | 同上 |
| **7 维权重调优** | 结果固化为快照，前端只展示"该快照已冻结生效" | 用户要的是"选出来能稳定复用"，不是权重数字 |

## 附：卖出提醒的四层触发机制（可直接落地的阈值清单）

行业共识里"该卖"由四类事件构成，**全部是确定性阈值，不含模型预测**——这是可解释、可自查、可手动复核，因此可信任：

| 层 | 触发条件 | 出处 | 对应我们现成模块 |
|---|---|---|---|
| L1 硬止损 | 成本价 −5% 无条件离场 | 打板工具通行纪律；通达信社区建议给每只持仓设 −5% 止损提醒 | `stop_loss.py` 单票止损 |
| L2 趋势破位 | **有效跌破 MA5**（打板圈共识："5 日线是短线生命线，线上做多线下空"）；辅以跌破 MA10/MA20 | 雪球短线总结；富途"跌穿 MA30"指标提醒 | `stop_loss.py` 组合止损 / `dynamic_stop.py` 移动止损 |
| L3 量能衰竭 | **炸板**（封单被砸开）、**放量长上影**、换手率异常（>30% 量增价跌 = 假放量出货）、盘中脉冲爆量后快速萎缩 | 同花顺"炸板"预警；九尾狐/换手抓板指标的止盈条款 | 需新写行情事件钩子（打板场景专用） |
| L4 指标死叉 | MACD 死叉、KDJ 高位死叉、RSI 超买回落 | 富途指标提醒（MA/EMA/KDJ/RSI/MACD/BOLL 全支持） | `unified_risk.py` 三层风控 |
| L5 浮盈锁定 | **跟踪止损**：从持仓期最高价回撤 X%（X≈5%）自动上移触发价，触及即离场 | 富途跟踪止损限价单（锁住浮盈同时让利润奔跑） | `dynamic_stop.py` |

**给用户的一句提醒**（写进 UI 的引导文案）：富途/通达信社区最常见的误用都是"**只设买入预警，不设风险预警**"。卖出提醒不能等用户自己配，必须由持仓回录**自动带上默认阈值**（L1 −5% + L2 MA5 + L5 跟踪止损），用户可改可关，但默认开启。

---

## 一句话建议

> **把首页从"今日推荐榜"改成"今日提醒收件箱"—— 让系统的中心对象从"今天有什么票"换成"我手里这些票今天有什么事"。**
>
> 具体三步：① 持仓+自选合并成唯一持久层；② 把 `stop_loss`/`dynamic_stop`/`unified_risk` 从回测里拔出来，接到这个持久层上，产出 L1/L2/L5 三档确定性卖出提醒；③ 给一条"我操作了"的轻输入，让提醒能自动带上阈值。
>
> 今天的候选不再是主角——它是**提醒的来源之一**（"你的自选里有 2 只命中今日候选"），而不是首页主体。
