### 已确认的整合缺口与重复候选

- 当前 `frontend/src/router.tsx` 注册今日、策略目录、因子、回测结果、市场环境、指数、数据状态、监控、个人复盘、自选、持仓、笔记、报告和个股研究等页面；`frontend/src/lib/ia.ts` 的 TickFlow 核心入口与 AQSP 个人操作系统并列。入口恢复不表示对应工作流/API都完整，缺口以本节的 route/API/存储矩阵为准。
- `backend/app.py` 的 `/api/aqsp/candidate/{symbol}` 与复数兼容路径 `/api/aqsp/candidates/{symbol}` 共用只读实现；`/api/candidate-observations/analyze` 提供独立候选分析，读/采用/停止/复盘 API 管理个人观察。候选观察由 `backend/candidate_observations.py` 独立存储，通过 `backend/live_risk_service.py` 的既有监控轮次离页检查，并用 notification runtime 对采用版本去重。浏览器自选仍在本地存储；未完成项转为真实模型稳定性、生产数据提醒质量、真实业务中多租户端到端和公网发布验收，不得把自动分析当成真实模型质量证明。
- 用户复盘 `/my/notes`、资料 `/my/reports`、候选讨论和持仓讨论具有不同用途。虽都有文本/AI内容，不能先合成单一记录；先核对各自写入、证据绑定、历史检索和用户的进入路径，再定义共用的“决策记录”字段。
- 这些是代码/路由初筛，不代表历史使用频率或生产访问量；兼容的单复数候选端点和旧路由先保留，待调用者/外部书签/迁移证据齐全再定退役。

## 3. AQSP 个人操作系统的统一模型

核心对象不是页面或策略数量，而是一条可复核的个人决策循环：

```text
今天要处理什么
  → 市场/个股/持仓当时可见证据
  → 量化筛选给出候选（确定性、可复现）
  → 本人问题、时间/资金/风险约束
  → AI 多空讨论（辅助判断，指出分歧和缺证）
  → 用户确认等待/操作条件及取消条件
  → 离页监控、变化解释、条件重核
  → 结果与执行事实回录
  → 对照当时证据的个人复盘
```

- **量化层**回答候选如何产生以及规则/数据是否有效；不由 LLM 改分。
- **个人判断层**记录用户的持有周期、可盯盘时间、风险承受、计划目的和本人判断；不从短期盈亏推断固定偏好。
- **AI 讨论层**读取可追溯证据，列方案、反方、条件和缺口；不能冒充事实、下单或替用户确认。
- **行动层**只保存明确确认过的条件和失效条件；候选与持仓分开建模，报价触达仅触发人工核验。
- **监控层**负责条件变化、失效、行情缺失、版本变化、去重和恢复，必须离页后仍能持续。
- **复盘层**把研究时依据、本人选择、执行偏差和后来结果并列，评估判断过程，不把回看结果当成当时可用信息。

## 4. 整合和删并的判定

先接入的是**完整能力认知与映射**。实现时每项只能落入以下一种结果，并记录代码证据、用户任务、迁移和验收：

1. **直接保留**：已有能力符合 AQSP 原则，纳入统一任务链，不复制。
2. **适配整合**：机制有价值，但改用 AQSP 的实体、数据源、人工边界和运行契约。
3. **补齐缺口**：当前无法完成明确的个人任务，先写数据/状态/失败模型，再纵向实现。
4. **审计后合并或退役**：有路由、调用、存储、任务、测试和历史兼容证据；先迁移并验证，再删除旧入口/重复状态。
5. **明确不纳入**：只增加平台复杂度或冲突于本项目宪法，记录原因，不进入实施队列。

不得仅凭文件名、页面相似、上游标注“已完成”或推测无人使用来删功能。删减验收是减少重复判断、重复状态、重复采集和维护成本，不是追求代码行数或页面数更少。

## 5. 长期实施顺序与完成标准

严格按 A→B→C→D 前进，前一阶段未验收不得跳到后一阶段。

| 阶段 | 交付目标 | 验收 |
|---|---|---|
| A. 完整 TickFlow 基线复刻 | 固定上游提交，覆盖完整功能手册、领域设计、可读源码和全部产品模块；逐页复刻布局、关键交互、状态与错误路径 | 每项有上游来源、AQSP 对应页面/API/服务/存储/任务/测试及桌面/窄屏验收。仅违反 AQSP 宪法或与单用户目标无关的扩展生态可不纳入，并逐项写清理由。A 未封口，不进入 B/C |
| B. 用户个人系统接入 | A 封口后，把用户已有复盘内容、判断维度、个人表达和操作顺序接入工作流 | 每项可追溯到原有资料/流程和 AQSP 领域对象；保留用户逻辑，不被通用模板覆盖；候选、持仓、策略保持清晰身份 |
| C. 合并强化与去重审计 | 从路由下钻到 API、服务、存储、后台任务、测试、历史数据和兼容入口；先迁移，再按证据保留、合并或退役 | 每项有依赖、迁移、对账、回滚和旧入口策略；迁移前不删除，不凭相似度或文件名判断重复 |
| D. 个人决策闭环 | 贯通市场发现、个股研究、策略/因子验证、人工决策、监控、持仓、成交回录和复盘 | 有持仓与零持仓任务均真实走通；过期、并发、断网、重复、越权可恢复；不自动下单 |

每个阶段都须完成纵向实现、针对性测试和真实页面验收；不得以文档覆盖、单次合成模型输出、目录规模或自动化测试代替用户任务证据。真实持仓数量、长期提醒噪音和真实模型稳定性各自记录，不拿合成样例冒充。

1. **封口阶段 A**：逐页对照 TickFlow 实际路由、全部 194 个前端源码文件、后端领域实现与 `docs/features.md`；每项未完成能力标明来源、依赖、AQSP 现状、阻断点与可见验收。
