# 持仓条件操作计划（2026-10-26）

## 最终交付中的当前单元：先诊断再选路（2026-10-27）

此单元属于 architecture.md §7.2 G1，仍不代表整个Goal完成。打开风险卡即可读取当前仓位事实、三条路各自的约束和缺证；无需先保存方案或填写数量/费率。旧大盘/板块检查证据须重核源时间，当前个股走势来自有效行情，缺失明确未知。可卖数量只说明交易约束，不冒充适合减仓或做T。

POST `/api/alerts/{event_id}/discussion` 的 `choice=null` 为选择前比较：同一模型三角色独立评估、交叉回应后，分别说明持有、减仓、做T的理由、缺口与分歧。有依据才给出可先核对的路线，否则保留不选；不自动写 `review_plan` 或修改成交。比较结果单独保存在同租户同仓事件中，变仓后不再展示；证据指纹绑定行情、三维源时间和风险检查，源变化或讨论过期时转为折叠历史分析，讨论中风险检查变化拒绝写入旧结论。结果携带生成时证据快照，避免服务端刷新报价后刚完成的分析与旧页面指纹不同而消失；读取期限与讨论生成时间分开，不拿收盘报价时间套用一分钟读取期限。`choice` 为已有路线时仍保留原方案讨论契约。

GET `/api/position-models` 只读取服务器当前提供商目录。目录有界限时/大小、正缓存与短失败缓存、刷新下限，无推理请求或自动升级；截断/分页未完整读取的目录不能证明型号缺失。目录故障仍允许用户按明确选择的型号尝试，不能误报为已下线。模型设置可选择已列出的型号，以 `server_model` 传给一次讨论；服务器重新核对目录，凭据仍仅在服务端。本设备偏好没有密钥，也不覆盖全局模型配置。型号从目录消失时要求用户重新选择；读取目录失败与型号不可用分开说明，目录列出不证明文本能力、费用或质量。完整模型成功证据与合成流程证据必须分开记录。

2026-10-27 故障定位：服务器显式配置 `agnes-2.0-flash`，提供商目录没有此型号，短请求返回500和型号暂不可用；目录已包含 `agnes-3.0-flash`，后者同端点同凭据短JSON请求返回200。默认示例更新不覆盖线上旧环境变量；线上切换需单独授权。完整候选编排已用合成持仓证据实连：该次三角色仅一名通过，未进入交叉回应及汇总，状态如实为 partial；短请求成功不能当作完整讨论恢复。后续须验证稳定性及发布，不向提供商发送真实持仓作测试。

用户指出，选择持有、减仓或做 T 后只有标签和固定说明，缺少对应买卖观察价和后续操作。本单元承接 architecture.md §7.1，补足三种选择的计划与费用测算，不更改选股/回测阈值。

## 使用与边界

- 在持仓风险卡选择方案，读取该仓位的最新行情。持有显示继续观察和退出复核条件；减仓显示反弹减仓与继续破低的复核分支；做 T 显示先卖、回落止跌后回补、追涨/破低时取消回补的分支。
- 观察价预填当前行情已见高低点；源时间与来源可展开。最近完成日不复权高低点仅在原检查有证据且日期仍匹配时补充。高低点是历史事实，不能称为已验证支撑阻力或到价买卖信号。
- 用户可修改价位，步骤同步使用本批价位。数量不预设仓位比例，佣金、最低佣金、卖出税费及滑点必须显式填写并确认。0 代表该测算不计此项，费用不冒充券商真实收费，旧模拟税率不自动带入。
- 做 T 以同股数先卖后买为测算前提，回补不得超过本笔实际卖出量；当前方案不代用户核实是否已成交，不自动产生“卖出完成”状态。每笔实际成交通过已有“我操作了”回录。未实现的情景收益不能累加为真实解套收益。
- 测算卖出收入减回补支出与两腿费用，现金保留两位、每股经济成本保留四位；负差价明确标注没有降低经济成本。减仓显示预计实现盈亏和剩余股数；全退出不除以零。
- 经济成本只从当前持仓投入减本次假设净现金计算，不能冒充券商成本或已实现收益；不包含用户未录入的历史买卖/分红/费用。
- 行情过期可查看旧参考，服务端拒绝新测算保存；界面每分钟要求刷新一次依据（只是保守刷新提示，不是策略阈值）。三维背景只有仍在同一交易日且板块源证据及时、当前个股仍走弱时，才能继承同步走弱的风险复核限制；缺少或过期证据降为未知。
- 计划绑定 position_id、成本、股数和可卖数量。持仓变化后旧测算失效；保存时再次锁内核对当前仓位，避免并发成交将旧计划写到新仓。跨租户、平仓重开、过量和 T+1 锁定都拒绝。
- 此功能是人工条件计划和算术测算，尚未做 walk-forward 验证，不提供适合做 T、收益概率或必然解套的结论。

## 模型持仓讨论

新增 POST /api/alerts/{event_id}/discussion。点击“分析当前方案”后，趋势、做 T、风控以同一服务端持仓证据分别调用模型；第二轮输入真实第一轮同行意见进行回应，最后汇总条件观察、分歧与缺证。角色不会预设立场，也不以多数表决改变风险规则。复用服务器 LLM_PROVIDER / 对应 API_KEY 与 MODEL；可使用本次填写的 OpenAI 兼容接口，凭据不落盘。当前实现如实标注同一模型三角色，不冒充三个独立模型。

每次最多 7 个调用，最多 3 个并发，两轮角色及汇总默认各45秒，可配置且每阶段最多60秒（#464起；I/O预算，不是策略阈值），HTTP 请求可取消、不重试、不跟随重定向，响应有大小上限。全进程共享非阻塞文件锁，已有任务时立即提示，不在 ECS 运行 CLI 或构建。部分角色失败保留各角色状态，并区分提供商HTTP错误、网络、超时与输出校验；不足两名完成交叉回应时不产生汇总，不拿固定模板伪装模型成功。前端使用 POST `/api/alerts/{event_id}/discussion/stream` 的有界NDJSON进度：准备、独立分析、交叉回应、汇总，每5秒心跳防止静默等待。断开取消本请求尚未完成的模型I/O并释放租约；保存线程一旦开始可能已完成写入，停止后提示刷新核对，不承诺撤回。无持久后台任务、自动重试或新daemon；同步接口保持兼容。

服务端校验引用 ID、结构化操作与可卖底仓/暂停回补约束，结构化价格只从服务端行情参考表读取。模型自由文字无法保证交易语义正确，默认折叠并明确标注未经验证；它不是成交指令，不能宣称已由规则验证为正确策略。原参数失效则拒绝讨论，讨论中变仓或换方案不写旧结果；跨标签刷新同步讨论版本，持仓变化后不再返回旧讨论。

## 2026-10-27 从选路到成交后的跟进

前轮只压缩了信息层级，仍缺少路线代价比较、当前等待状态与成交后的下一步。本轮在现有链路内补齐：

- 读取当前有效价与用户观察价，展示距离、到价但转弱未确认、跌破低点需复核；不把触价升级成技术形态或买卖信号。页面可见时沿用60秒只读刷新，恢复焦点和成交事件立即刷新。无新增cron或外发到价提醒。

- 无法确认用户该笔成交是否属于做T，不自动标记做T第一腿完成；不自动把普通加仓当回补，实际买回仍须人工录入。
- 保留行情时效、T+1、三维同弱、变仓及跨租户限制；明确可见页刷新和既有风险推送的能力不同。

卖出后的确认与重新选择分开：切换到观察不冒充核对完成，用户须点“已核对余仓，继续观察”；服务端锁内复核当前仓位后保存确认。重新试算确认最新卖出编号，未确认的新成交会使旧试算与讨论失效。卡片卖出入口复用全局逐笔操作编号与断网草稿，同一提醒允许记录多次真实部分卖出，不改变旧事件成交接口的恢复语义。
