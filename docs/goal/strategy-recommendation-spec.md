# Spec：可运行、可验证的有效策略推荐方案 V1

## Objective

为单用户 A 股研究工作台建立一条可运行的推荐闭环。用户在交易日收盘后能看到：

- 当前研究日期、市场/行业背景和数据时点；
- 通过硬门禁的候选及其策略版本、评分、理由、反证、风险和下一观察条件；
- 不能推荐时的具体阻断原因；
- 推荐是否来自当日有效研究，历史结果与当前机会严格分开；
- 采用后能在离页状态下持续检查条件，并在有意义变化时提醒。

“有效”必须同时满足：代码可运行、数据无未来泄漏、回测通过预先定义的 OOS/CSCV/PBO/成本/可成交性门槛、运行产物新鲜且可追溯、推荐页面与通知不隐藏缺口。一次合成测试、一次模型成功、一个前端页面或一份历史高收益报告都不能单独证明有效。

## 技术边界

- Python 3.10+，前端沿用现有 React/TypeScript。
- 不自动下单，不接券商，不引入 LLM 评分或权重学习。
- 回测使用不复权价格 + PIT 复权因子；禁止未来数据、中心化 rolling、全期归一化。
- 阈值只来自 `config/thresholds.yaml` 或经验证的版本化配置。
- 运行数据留在私有 runtime root；GitHub 只保存代码、测试、文档和可复现配置。
- 服务器不构建 npm/vite，不跑重型实验；发布采用本地制品和 immutable release。

## 数据与策略合同

每条候选必须绑定：研究日期、策略/阈值版本、参数指纹、行情源与源时点、行业/市场证据身份、研究任务身份、可成交性结果和失效条件。任何字段缺失、过期、未来、单位/周期不符或来源未知，都进入 `unknown`/`blocked`，不能降级成零值或继续作为推荐依据。

策略版本必须有：

1. 预先冻结的候选池和特征定义；
2. 训练/验证/测试时间边界；
3. 最低样本量、冷却期和失败状态；
4. 交易成本、涨跌停、停牌、T+1 和不可成交处理；
5. OOS 结果、CSCV/PBO 或等价多重检验记录；
6. 不同市场背景和至少两个时间窗口的一致性判定；
7. 发布后自然运行的产物新鲜度和回滚点。

## 阶段任务

### S0 基线与规格

建立能力地图、策略版本状态机、证据字段清单、运行/发布/回滚验收矩阵。清理当前文档中把“页面可用”“合成讨论”“历史产物”写成策略有效性的表述。

### S1 数据完整性

对候选所需的行情、行业、市场宽度、财务/事件源做 PIT、时点、覆盖率、单位、空值和未来日期审计；为每个失败路径保留结构化 reason，并让推荐门禁消费同一份事实。

### S2 策略研究与验证

从现有已实现策略中选择少量可解释候选，建立冻结配置和 walk-forward 运行。先验证数据覆盖与可成交性，再比较收益；不因负结果调参，不把最优变体直接提升为生产策略。

### S3 运行推荐

修复 daily/variant/runner 的启动、锁、失败、超时、旧产物覆盖和状态可见性；保证每个交易日都有成功、等待、阻断或失败状态，且首页/通知与状态一致。

### S4 推荐解释与监控

把候选理由、反证、风险、条件、来源和未知项统一到前端与通知；采用后的条件逐项核验，普通刷新不重复提醒，源变化和条件失效可解释。

当前合同：前端从 ledger 生成候选卡片时，必须同时读取当前日 home snapshot 的
`recommendation_gate`；gate 未通过时，当前日的 `research_recommendation` 只能降级为“观察”，历史日期仍按归档记录展示。

### S5 发布与自然运行验收

完成本地门禁、CI、immutable release、公网 health/路由/快照检查；随后观察至少一个完整自然运行窗口，分开记录代码、制品、上线、数据新鲜度、真实模型和真实用户持仓验收状态。

## 完成判据

只有以下条件全部有证据时，才可把某个策略版本称为“可运行的有效推荐”：

- 代码、测试、ruff、secret/preflight 和 CI 通过；
- PIT/时点/覆盖率/单位/可成交性审计通过；
- 两个以上时间窗口的 OOS 验证满足预先冻结门槛，且未触发 PBO/CSCV/成本/样本量阻断；
- 当日运行产物成功且研究日期、来源时点、策略版本一致；
- 页面与通知只展示当前有效证据，失败/未知/历史状态明确可见；
- 至少一个完整自然运行周期没有静默沿用旧产物或误发推荐；
- 发布后可回滚，回滚演练或等价只读验证有记录。

## 明确延期

- 自动交易、券商接入、实盘下单；
- 以 LLM 替代确定性评分或硬风控；
- 无 walk-forward 证据的新因子族上线；
- 为了让推荐变多而放宽数据新鲜度、来源、样本量或可成交性门槛；
- 仅凭一次真实模型调用、一次人工持仓或短期收益宣称策略有效。

以当前 `main` 为基线，先由并行审计确认：候选研究/验证的真实断点、#490 技术指标来源合同、#693 启动/调度可见性、#462 模型完整讨论稳定性，以及至少一个策略版本能否在现有数据覆盖下完成双窗口 OOS 验证。未确认前不选定具体买入策略。
