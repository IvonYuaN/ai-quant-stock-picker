# 重构 PRD 交接材料（主理人汇编）

> 供 requirement-analyst（析客）撰写重构 PRD 使用。日期 2026-10-19。

## 一、用户（仓主）的原话与优先级

用户是 A 股 **T+1 实盘**短线交易者，有自己的交易软件（不靠本系统下单）。原话：

> "我早中午进去都是一批新的内容，这个选出来你 ai 分析团队还有策略是可以随时变化的，但是我的资金实盘买卖是 T+1 的。你应该从用户角度去看看这个内容的合理性。
> 我的这个板块太多余了，持仓自选合并以后就够了。其他你又不能实盘交易，我有交易软件，还用这个系统干嘛。
> 我的优先级是：你合理的小道消息 + 选股 + 大盘行情。然后分析我买不买、卖不卖的。我实盘处理完我输入一点信息，你后续帮我强化分析和跟进。如果需要卖了你就得提醒。
> 你现在逻辑很乱，纯粹为了做而作，没有一点逻辑思考。"

**核心定位**：本系统 = **T+1 实盘用户的决策工作台**（副驾驶），不是"每日换一批候选的研究员仪表盘"。

## 二、主理人核实的代码事实（技术锚点）

结论一句话：**缺的从来不是能力，是接线。零件齐全、调用为零。**

| 用户痛点 | 代码真实情况 |
|---|---|
| 早中晚一批新内容 | 根因：`portfolio/snapshot.py` 只做每日留档+跨日对比，`save_snapshot` 每次跑 `screen_universe`（cli.py:4765/5239）就整批重算重存，**无"当日冻结"闸门**。修复零件已有（save/load_snapshot）。 |
| 该卖没人提醒 | 风控引擎齐全能吃实盘持仓：`StopLossManager.check_single_stock_stop/check_all`、`UnifiedRiskManager.check_all`、`dynamic_stop.py`（ATR+支撑位）、通知去重 `notification_runtime.should_send_notification`。但 `portfolio/manager.py:816` 只把 stop_loss 当展示字段，**全仓无一处**对实盘持仓跑风控产提醒。 |
| 实盘操作无输入通道 | `backend/portfolio.py` 有 `add_holding`/`close_position` 数据结构，但 UI 无顺手"我今天买了/卖了"回录入口。 |
| 板块多余 | `ConceptsPage.tsx` 路由存在但**未进 `ia.ts` NAV_LINES**（半隐藏，最该砍）。 |
| 持仓自选分裂 | `HoldingsPage.tsx` / `WatchlistPage.tsx` 两独立页。 |

## 三、两份诊断已收口（详见 _research/）

### 瑞思（用户视角）—— 3 个 P0 断点
- **P0-1 候选日内全换** → 盘前冻结+盘中增量标注。
- **P0-2 无操作回录入口** → 全局"我操作了[代码/方向/价格/数量]"。
- **P0-3 无卖出提醒** → 风控接实盘持仓。
- P1 板块冗余、持仓自选合并；P2 量化指标用户不消费。
- 核心 loop 三断点：③持仓/自选分裂+板块干扰 ④候选日变 ⑥无回录 ⑦无提醒。

### 竞析（竞品对标，6 个对标）—— 心智模型
- ★★ **所有被信任工具首页中心对象都是"我的持仓/自选"，无一例外是"今日推荐"。连 Qlib 产物都是 target position（目标持仓）而非推荐榜。**
- **信任四属性**：对象稳定 / 输入可控 / 输出可执行 / 不打扰 —— 本系统四条全违约 ⇒ "早中晚不一样"是机制性失败。
- **"该卖提醒"全行业不靠模型预测，全是确定性阈值**（可解释=可信任）。
- 可抄机制：富途「我的提醒」跨股票聚合收件箱（只列触发了什么）；提醒频率三档防打扰；通达信误用=只设买入预警不设风险预警 ⇒ **卖出阈值须回录持仓时自动挂默认**。
- 卖出五层阈值：L1 硬止损(成本−5%) / L2 跌破 MA5 / L3 炸板·放量长上影·换手>30%(需新写行情钩子) / L4 MACD死叉 / L5 跟踪止损(只升不降)。**L1/L2/L4/L5 全部现成**。

### ⚠️ 待老大拍板的分歧
瑞思主张"小道消息置顶"，竞析主张"消息流折叠为 tab（它是输入源非状态）"。PRD 里先按**竞析方案（折叠）**并标注备选。
