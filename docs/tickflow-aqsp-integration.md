### 已确认的整合缺口与重复候选

- 当前 `frontend/src/router.tsx` 注册今日、市场、资讯、持仓、持仓计划、笔记、报告和个股研究等页面；`frontend/src/lib/ia.ts` 主要导航展示今日/持仓/大盘/消息四项，并将其他旧系统页重定向到今日。导航收敛是既有选择，不等于数据/服务已合并。笔记、报告、个股研究等页面要经由任务链/卡片进入，后续验收须覆盖实际可发现性。
- `backend/app.py` 的 `/api/aqsp/candidate/{symbol}` 与复数兼容路径 `/api/aqsp/candidates/{symbol}` 共用只读实现；候选生命周期也只读。浏览器自选在 `frontend/src/pages/StockResearchPage.tsx` 通过本地存储加载。当前可确认有候选快照/讨论和浏览器自选；未发现持久候选观察的创建、停止、离页检查 API。这是候选闭环缺口，不应通过伪造持仓身份填补。
- 用户复盘 `/my/notes`、资料 `/my/reports`、候选讨论和持仓讨论具有不同用途。虽都有文本/AI内容，不能先合成单一记录；先核对各自写入、证据绑定、历史检索和用户的进入路径，再定义共用的“决策记录”字段。

## 3. AQSP 个人操作系统的统一模型

核心对象不是页面或策略数量，而是一条可复核的个人决策循环：

```text
今天要处理什么
  → 市场/个股/持仓当时可见证据
  → 量化筛选给出候选（确定性、可复现）
  → 本人问题、时间/资金/风险约束
  → AI 多空讨论（辅助判断，指出分歧和缺证）
  → 用户确认等待/操作条件及取消条件
  → 离页监控、变化解释、条件重核
  → 结果与执行事实回录
  → 对照当时证据的个人复盘
```

- **量化层**回答候选如何产生以及规则/数据是否有效；不由 LLM 改分。
- **个人判断层**记录用户的持有周期、可盯盘时间、风险承受、计划目的和本人判断；不从短期盈亏推断固定偏好。
- **AI 讨论层**读取可追溯证据，列方案、反方、条件和缺口；不能冒充事实、下单或替用户确认。
- **行动层**只保存明确确认过的条件和失效条件；候选与持仓分开建模，报价触达仅触发人工核验。
- **监控层**负责条件变化、失效、行情缺失、版本变化、去重和恢复，必须离页后仍能持续。
- **复盘层**把研究时依据、本人选择、执行偏差和后来结果并列，评估判断过程，不把回看结果当成当时可用信息。

## 4. 整合和删并的判定

先接入的是**完整能力认知与映射**。实现时每项只能落入以下一种结果，并记录代码证据、用户任务、迁移和验收：

1. **直接保留**：已有能力符合 AQSP 原则，纳入统一任务链，不复制。
2. **适配整合**：机制有价值，但改用 AQSP 的实体、数据源、人工边界和运行契约。
3. **补齐缺口**：当前无法完成明确的个人任务，先写数据/状态/失败模型，再纵向实现。
4. **审计后合并或退役**：有路由、调用、存储、任务、测试和历史兼容证据；先迁移并验证，再删除旧入口/重复状态。
5. **明确不纳入**：只增加平台复杂度或冲突于本项目宪法，记录原因，不进入实施队列。

不得仅凭文件名、页面相似、上游标注“已完成”或推测无人使用来删功能。删减验收是减少重复判断、重复状态、重复采集和维护成本，不是追求代码行数或页面数更少。

| F. 逐项删并与运行治理 | 根据 B 的证据迁移并移除确认重复入口/状态，统一任务、来源和通知状态，保留审计和旧链接过渡 | 迁移前后状态可对账，旧入口有明确转向，生产回滚可行；真实用户任务未退化 |

每个阶段完成完整的纵向交付、定向测试和真实使用表面验证；不得以文档覆盖、单次合成模型输出、目录规模或自动化测试代替用户任务证据。真实持仓数量、长期提醒噪音和真实模型稳定性各自记录，不得拿合成样例冒充。

## 6. 当前优先缺口（按依赖排序）

1. **补全现状证据引用**：矩阵先标出实际 AQSP 路由、服务/模块及状态文件；将不清楚的职责重复列成待核实，不把已实现标签当成端到端完成。
2. **建立统一的个人决策记录**：检查 `review`、`notes`、`reports`、`decision_chain`、持仓工作区和候选/策略 ledger，决定哪些字段是“当时证据/本人理由/AI 分歧/采用条件/执行事实/复盘结论”，避免再造第二本笔记或交易账。
3. **打通缺失的未持仓候选闭环**：以独立候选身份接入已建立的证据与决策模型，补齐讨论、确认、离页监控和复盘；这是统一模型审计后的首个完整业务切片，而不是总体整合本身。
4. **再做页面和状态删并**：按真实依赖迁移，保留兼容；优先消除重复摘要、同义提醒、同一任务的第二套状态。
5. **最后对研究生命周期做收敛**：研究成熟度不通过页面合并伪造，按实际策略/因子版本与 OOS 证据渐进统一。
