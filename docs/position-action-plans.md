# 持仓条件操作计划（2026-10-26）

用户指出，选择持有、减仓或做 T 后只有标签和固定说明，缺少对应买卖观察价和后续操作。本单元承接 architecture.md §7.1，补足三种选择的计划与费用测算，不更改选股/回测阈值。

## 使用与边界

- 在持仓风险卡选择方案，读取该仓位的最新行情。持有显示继续观察和退出复核条件；减仓显示反弹减仓与继续破低的复核分支；做 T 显示先卖、回落止跌后回补、追涨/破低时取消回补的分支。
- 观察价预填当前行情已见高低点；源时间与来源可展开。最近完成日不复权高低点仅在原检查有证据且日期仍匹配时补充。高低点是历史事实，不能称为已验证支撑阻力或到价买卖信号。
- 用户可修改价位，步骤同步使用本批价位。数量不预设仓位比例，佣金、最低佣金、卖出税费及滑点必须显式填写并确认。0 代表该测算不计此项，费用不冒充券商真实收费，旧模拟税率不自动带入。
- 做 T 以同股数先卖后买为测算前提，回补不得超过本笔实际卖出量；当前方案不代用户核实是否已成交，不自动产生“卖出完成”状态。每笔实际成交通过已有“我操作了”回录。未实现的情景收益不能累加为真实解套收益。
- 测算卖出收入减回补支出与两腿费用，现金保留两位、每股经济成本保留四位；负差价明确标注没有降低经济成本。减仓显示预计实现盈亏和剩余股数；全退出不除以零。
- 经济成本只从当前持仓投入减本次假设净现金计算，不能冒充券商成本或已实现收益；不包含用户未录入的历史买卖/分红/费用。
- 行情过期可查看旧参考，服务端拒绝新测算保存；界面每分钟要求刷新一次依据（只是保守刷新提示，不是策略阈值）。三维背景只有仍在同一交易日且板块源证据及时、当前个股仍走弱时，才能继承同步走弱的风险复核限制；缺少或过期证据降为未知。
- 计划绑定 position_id、成本、股数和可卖数量。持仓变化后旧测算失效；保存时再次锁内核对当前仓位，避免并发成交将旧计划写到新仓。跨租户、平仓重开、过量和 T+1 锁定都拒绝。
- 此功能是人工条件计划和算术测算，尚未做 walk-forward 验证，不提供适合做 T、收益概率或必然解套的结论。

## 实现

`position_action_plan.py` 负责纯价位证据和 Decimal 两腿计算；`position_plan_service.py` 负责租户、时效与原子持久化。复用原方案 POST 接口，旧 choice-only 客户端仍可用；新增 GET `/api/alerts/{event_id}/action-plan` 返回最新依据、原参数及重算结果。前端选择后懒加载，改参数即隐藏旧结果；保存中禁用编辑，断网保留草稿并允许原样重试。

## 验证

实际命令和发布状态记录在当前 PR。单元/API 覆盖净差价、费用、减仓亏损、板块回补单位、无行情/过期/未来日线、调整口径、跨租户/重开/并发/存储失败。独立无头验收仅使用隔离合成租户与临时服务，不写入生产持仓、不发送通知；截图与运行输出在本地临时目录。


## 模型持仓讨论

新增 POST /api/alerts/{event_id}/discussion。点击“分析当前方案”后，趋势、做 T、风控以同一服务端持仓证据分别调用模型；第二轮输入真实第一轮同行意见进行回应，最后汇总条件观察、分歧与缺证。角色不会预设立场，也不以多数表决改变风险规则。复用服务器 LLM_PROVIDER / 对应 API_KEY 与 MODEL；可使用本次填写的 OpenAI 兼容接口，凭据不落盘。当前实现如实标注同一模型三角色，不冒充三个独立模型。

每次最多 7 个调用，最多 3 个并发，两轮角色各有 18 秒上限、汇总 12 秒上限，HTTP 请求可取消、不重试、不跟随重定向，响应有大小上限。全进程共享非阻塞文件锁，已有任务时立即提示，不在 ECS 运行 CLI 或构建。部分角色失败保留各角色状态；不足两名完成交叉回应时不产生汇总，不拿固定模板伪装模型成功。

服务端校验引用 ID、结构化操作与可卖底仓/暂停回补约束，结构化价格只从服务端行情参考表读取。模型自由文字无法保证交易语义正确，默认折叠并明确标注未经验证；它不是成交指令，不能宣称已由规则验证为正确策略。原参数失效则拒绝讨论，讨论中变仓或换方案不写旧结果；跨标签刷新同步讨论版本，持仓变化后不再返回旧讨论。
